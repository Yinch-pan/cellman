# i18n 后完整对局与 BGA 交互复核

日期：2026-10-25。用户要求用项目模拟一整局，并判断是否流畅、是否与 BGA 操作几乎一致。本次仅本地验收，不发布，不推进用户原有对局。

## 方法与判断标准

四个独立登录会话，顺蛇轮抽、四人大地图，包含 390×844 手机视口。从页面登录、创建房间、加入、准备和开局开始，通过实际按钮操作到六轮结束。测试账户预置；游戏局面和资源没有注入。每次确认后比较四端局面，中途断网恢复并刷新，最后导出行动记录并回放核对。

完整局采用逐步提交模式，以逐次检查服务器提交与四端同步。默认的本回合试走/整回合提交另外做专项验收，不能把逐步提交局说成默认模式完整局。模拟策略由规则引擎筛选合法操作，验证可完成性，不是独立的规则正确性裁判，也不评价策略水平。

BGA 对照依据是此前实际完成的房间 937134162、操作笔记与截图，本次没有重新操作 BGA。参考局为两人，本项目测试局为四人；只对照交互流程，不按点击总数或得分直接比较。

流畅性分开判断：①无阻塞、报错、重复扣费或同步分叉；②操作入口是否直观，是否需要额外翻页、滚动、重复确认；③规则与视觉是否逐项相同。完整局通过只能证明本次走过的链路，不能直接证明后两项。

## 本轮修正

- 实际结束本轮预览截图发现：通用 `.preview-panel > div` 的横向 flex 把标题、警告和顺位说明挤成三列。对 `.pass-review` 单独采用纵向 grid；补拍修正截图并验证取消仍不改变轮次。
- i18n JSON 导入补上标准导入属性，使完整浏览器测试脚本在 Node 环境也能加载语言包；没有改变翻译或游戏规则。
- 完整对局驱动的“推进航行”更新为页面现有“推进航海”。
- 给完整局增加各类行动预览截图与操作/同步耗时记录；耗时包含自动化点击和界面等待，不是公网网络延迟或性能基准。
- 默认试走联机验收改为使用测试端口变量，避免访问用户正在使用的 5174 服务。
