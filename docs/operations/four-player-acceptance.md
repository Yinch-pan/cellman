# 四人模拟对局与本地验收

验证日期：2026-10-23。用户确认本阶段先完成本地验收，之后再决定服务器。本次使用四个独立账号、四个隔离 Chrome 会话模拟玩家，其中一端使用 390 × 844 手机尺寸；这是自动化模拟，不是四名真人的规则评审。

## 已复现并修复

1. **联机公共魔力行动无法提交**：金币、工具、学者行动错误携带空桥梁坐标，通过本地规则预览却被 HTTP 输入校验拒绝。现在只有建桥动作才携带桥位。
2. **存档后回放顺序不确定**：PostgreSQL jsonb 会重排对象键，旧引擎依赖对象遍历顺序，完整对局可能出现成绩数组顺序不同，甚至待响应编号对应到另一玩家。新规则 `aoi-1.1+2024-09.engine-3` 在每步行动前统一对象键顺序，保留数组中的回合及效果顺序。v1、v2 冻结兼容；旧联机导出增加 `storage: postgres-jsonb`，使用 `replayRecord` 按原存储行为重放。
3. **限流配置没有生效**：路由先于插件初始化，未安装限制钩子。现在在插件初始化后注册路由，登录、注册、恢复按 IP 限制；普通请求按已认证账号限制，同一网络的玩家互不挤占额度，同一账号换会话也不能重置额度。
4. **选择框与实际动作不一致**：随机书籍动作默认值固定为未必存在的 `power`；被其他人占用的公共动作、学者位置、宫殿、创新和奖励板可能留下失效值。现在根据当前可用选项生成实际选择，已耗尽动作禁用提交。
5. **较早行动记录被刷新覆盖**：向前翻页后收到实时更新会退回最新 100 条。现在按版本合并并去重。
6. **账号及房间异常处理**：退出登录失败现在显示错误且保留账号；离开房间失败留在原房间，可重试；注册成功后立即保留恢复码，即使自动登录失败也能保存并再次登录。
7. **房间及手机界面**：显示真实人数与开局方式；手机座位采用两列，长用户名换行，页头避免挤压。切换房间时隔离组件状态。
8. **终局显示不一致**：顶部玩家卡片仍显示局内分，与结算总分不同。现在终局卡片显示总分，并禁用终局后的设置提交。

## 验证方式

- 规则与数据库：138 项检查、29 个文件；其中 24 局三至五人有实际战略行动的模拟，检查每步资源、六轮结束、计分加总、完整状态与事件回放一致。另有旧 v2 五人完整存档回放。
- 随机模拟每个动作都经过规则合法性校验，没有注入额外资源。四种偏好覆盖升级、扩张、学科及书籍/创新；这用于发现流程问题，不是独立规则裁判，也没有穷尽所有特殊能力组合。
- 三、四、五人 HTTP/SSE 测试均通过真实创建房间、准备、开局，覆盖权限、同步、重复提交、并发版本冲突、重连和应用重启。已移除四、五人绕过房间直接插入游戏的旧测试捷径。
- 浏览器：17 项全套检查通过；最后的终局显示修复后，8 项受影响检查通过（含 1 项新增用例），合计覆盖 18 项用例。包括完整四人开房、选配、放置、六轮行动、逐步四端一致性、刷新恢复、终局和导出回放；同时保留丢失响应、网关错误、移动布局及历史记录回归。
- 本次四人浏览器对局共 **262 次有效提交**：4 次选配、8 次放置、20 次升级、6 次改造建造、18 次派遣学者、12 次技术升级、14 次魔力公共动作、6 次书籍动作、1 次创新、72 次奖励响应、77 次结束回合、24 次结束轮次。四名玩家最终得分依次为 **93、72、54、85**。导出回放与服务端局面完全一致。
- TypeScript 类型检查与前端生产构建通过。
- 规则引用目录 inventory 检查通过；**M3 完整规则验收未通过**，目录中 166 项仍未标记为独立核验。没有为了让检查变绿而改写这些状态。

## 本机容量与备份恢复实测

`scripts/check-local-operations.ts` 只允许本机独立 `TEST_DATABASE_URL`，创建本次随机 schema 和恢复数据库，并在结束后清理；不操作开发库。

- 100 个模拟账号、100 条 SSE 连接、25 个四人房间。
- 400 次局面读取、25 次预览、25 次提交，共 450 次 HTTP 请求，错误 0；100 个客户端都收到更新。
- 本次 p95：局面读取 170.2 ms、预览 46.8 ms、提交 57.8 ms。
- 用 PostgreSQL 17 的 `pg_dump` 备份测试 schema，并通过 `pg_restore` 恢复到新建临时数据库。
- 核对恢复后的 100 个账号和 25 局游戏、局面及回放，恢复库成功从版本 1 继续到版本 2；源库仍为版本 1。
- 这是本机短时并发测试，与浏览器回归同时运行。尚未验证公网延迟、长期负载、多服务进程通知或目标生产环境的备份策略。

详细测量在本机 `work/acceptance/local-operations.json`；测试备份仅含合成账号数据，位于被 Git 忽略的 `work/acceptance/`。

四人局原始记录保存在 `work/acceptance/four-player-replay.json`，行动统计在 `work/acceptance/playthrough-summary.json`。`four-player-mobile.png` 为试局中的手机截图；`four-player-finished.png` 使用实际完整记录重放后的终局重新渲染，并验证顶部总分与结算一致。

6. 鼹鼠公共建桥列出跨陆地桥位，排除已占用桥；幻术师公共行动显示实际折扣价格。
7. 书籍输入有可见颜色、持有量和已选总数，可填入一组满足条件的组合后自行调整；不会自动提交或宣称推荐了最优支付。
8. 玩家、建筑、桥梁和学科标记采用一致的家园颜色；空特殊行动区域不再占位。预览出现时自动定位确认区。
