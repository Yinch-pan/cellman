# Snellman 参考迁移与试玩说明

## 2026-10-23：历史回看、悔棋与统计

在 Snellman 的可重放命令和资源账本基础上，已增加以下用户入口：

- **行动记录**：玩家/轮次筛选、自我上次行动后的记录、每条记录查看历史局面、上一步/下一步、返回当前局面。历史视图禁用所有行动；被撤销的原行动保留并标注，仍可查看。
- **联机悔棋**：从本人仍有效的行动发起申请，预览恢复位置、填写原因。该行动及其后的依赖行动一起撤销，所有玩家同意才生效；等待时暂停提交。任一玩家可拒绝，申请人可取消。请求、投票和恢复在数据库事务中串行化，重复请求不会重复恢复；不需要房主直接编辑原始历史。
- **同屏撤回**：同屏玩家确认后恢复；新状态和完整记录一并保存在浏览器，刷新后仍可重放。
- **本局数据统计**：按玩家显示各轮分数/资源净变化、行动次数、按触发行动归因的分数、终局加分。撤销分支不计入有效统计，统计从存档真实可用的回放起点开始。资源净变化不是总收入/总支出；触发行动归因也不是逐个能力的精确收益拆分。轮末自动结算归入触发行动所在轮次。
- **战绩统计**：导航栏入口，显示个人完成局数、胜率、均分、最高分、种族表现、最近 100 局；全站种族统计可按 3/4/5 人筛选，并比较起始顺位。并列第一平分胜场权重，不等同于 Elo 排名。

迁移 `003-undo.sql` 新增悔棋申请表和统计资格标记。已有对局默认不进入正式战绩统计；新建标准联机局纳入，入门/同屏局不纳入。待确认悔棋的终局暂时排除，恢复到未结束时自动退出统计，避免重复结算。

回退本身追加一个新的 `restore` 记录，版本号单调递增，原始命令不删除。含撤回的导出格式为 `yijian-replay-v2`，无撤回仍为 v1；两者都使用当前 `replayRecord` 重放。旧引擎行为继续保持冻结。已有 v1 文件可继续使用，但旧版外部工具不能理解 v2 的恢复指令。

验证入口：`pnpm test`、`pnpm build`、`pnpm exec playwright test tests/e2e/review-undo.spec.ts`。新增覆盖四浏览器同意/拒绝/取消、刷新和导出重放、旧提交重试、并发投票、旁观账号越权、关联蹭魔回退、六轮模拟中途回退后继续完局，以及撤回后的统计核对。

本次验证：145 项规则/数据库测试通过，19 项浏览器回归通过（未重复此前约七分钟的完整四人 UI 长局；本次新增四人悔棋浏览器用例，以及中途回退后完整六轮的规则模拟）。最后的导出审计字段与统计分组调整又通过相关 10 项测试，生产构建通过。完整浏览器套件中的账号创建会遵守实际限流的 Retry-After 等待，不关闭生产限流来绕过检查。

参考源码仍为下文固定版本的 Snellman。以上功能在本项目 TypeScript 架构中独立实现，没有复制上游源代码或素材。此更新不改变下文保留的历史规则验收限制。

后续四人完整试局发现并修复了联机提交、回放确定性、限流与界面问题。当前新对局使用 engine-3，engine-2 已冻结保留。最新结果见 [四人本地验收](four-player-acceptance.md)。本文以下为原迁移记录。

本次把现有三人固定预览扩展为 **3–5 人随机选配测试版**。可同屏轮流游玩，也可用不同账号创建房间、准备并开始对局。开发服务仍只监听本机；不等于已经发布公网。

## 开始游玩

运行 `scripts/start-local.ps1`，打开 http://127.0.0.1:5173/ 。

1. 无需账号：点击“先看看游戏桌面”，选择人数，点击“新开随机对局”。
2. 从末位玩家开始选择“种族 / 家园 / 奖励板”组合；同屏模式自动切换到下一位待行动者。
3. 按提示放置起始建筑、处理开局奖励，再进入六轮行动。选择地图地块后预览行动，确认后生效。
4. 联机：每位玩家用自己的账号加入房间并准备，房主开始对局。大厅可选择随机选配或三人入门配置。
5. 任何行动后的蹭魔、能力、书籍、城市等选择，都在待响应区域处理。特殊行动显示于个人行动区域。
6. 展开“行动记录”查看资源增减；“导出对局记录”下载带初始局面与逐条命令的 JSON。当前没有网页导入回放播放器，导出文件由规则模块 `replayGame` 校验并可重建局面。

“重新开始”恢复三人入门局；“新开随机对局”会替换当前浏览器的同屏存档。需要保留时先导出。联机存档在 PostgreSQL，不受同屏重开影响。

## 从 Snellman 学到并实现的部分

参考 [jsnell/terra-mystica](https://github.com/jsnell/terra-mystica)，检视版本 [6e5d1cdef1f94c87baf8780457e756c12760b292](https://github.com/jsnell/terra-mystica/tree/6e5d1cdef1f94c87baf8780457e756c12760b292)。该仓库主要是神秘大地，不作为大创造时代规则依据。

| 参考机制 | 在本项目中的实现 |
| --- | --- |
| 可重放命令、局面校验 | 保存初始局面、规则版本和有序原始行动；`replayGame` 检查版本连续及每步合法性 |
| 资源账本 | 每条成功行动记录所有受影响座位的金币、工具、书籍、魔力、学科、钥匙、分数变化与前后值 |
| 明确的待响应 | 记录触发版本、来源、依赖与效果组；工程宫殿的成组奖励不能穿插处理 |
| 数据驱动能力 | 种族、宫殿、创新集中定义名称、说明、来源页码与能力入口 |
| 长局记录与兼容 | 历史记录向前翻页；旧引擎冻结在 `packages/rules/legacy/v1`，旧存档继续按原版执行 |

没有复制上游 Perl/JavaScript 源码或美术素材；以上是在本项目 TypeScript 架构中独立实现的设计。上游使用 MIT 许可。本项目地图与建筑继续使用自制图形。

## 规则与内容范围

实现入口包含 12 个种族、17 个宫殿、18 个创新、12 个能力板块、10 个奖励板、12 个轮次板块，以及 3/4/5 人随机准备、逆序选配、起始建筑差异。规则依据为 [英文规则 1.1](https://capstone-games.com/cdn/shop/files/AoI_rules_EN_V1-1_reduced.pdf?v=10451577216657094607) 与 [2024 年 9 月修订](https://www.feuerland-spiele.de/fileadmin/game/Age_of_Innovation/AoI_Aenderung_09_24.pdf)，来源哈希见 `docs/rules/sources.json`。

这些入口并不意味着全部组合已经独立验证。当前仍缺少双人小地图逐格核对、完整来源案例覆盖和熟悉规则玩家的真人试局；M1/M3 覆盖门槛仍未通过。地图、少见连锁与终局组合需要继续对照官方案例。未加入扩展、AI、排位、观战或公网部署。

## 数据升级

`002-replay.sql` 只新增字段和索引。已有对局以迁移时的局面作为回放起点，不伪造过去未保存的原始行动；新对局可从开局回放。旧规则版本 `aoi-1.1+2024-09` 保持冻结，新对局使用 `aoi-1.1+2024-09.engine-2`。以后有规则语义变化应新增版本，不直接改变已冻结的回放行为。

## 验证范围

- Vitest：132 项、28 个文件通过，包含真实 PostgreSQL、3/4/5 客户端同步、并发与重试、随机开局、六轮流程、完整命令回放和新能力入口。
- Playwright / Chrome：9 项全部通过，含原有 6 项与新增 3/4/5 人随机选配、刷新、导出用例。
- TypeScript 类型检查、Vite 生产构建通过；166 项规则引用目录检查通过。
- 六轮基线的人工期望仍为 73、51、53 分；随机六轮用例主要核对阶段流转和重放一致性，不能代替复杂战略组合的独立计分算例。
- 新增边界回归覆盖工程宫殿奖励组、升级释放商会供给、自动蹭魔结束收入阶段、旧规则存档回放。

原三账号浏览器测试与多人传输测试的已有工作保留，并与此次改动共同运行；不将其全部计作本次新增。
