# DIY 能力配置首版建议（待实现）

日期：2026-10-26。依据：[现有能力盘点表](diy-ability-inventory.md)，规则基线 `aoi-1.1+2024-09.engine-6`。

这是一份由实际代码边界推导的设计建议。仓库目前没有下述配置解析器、内容包导入、房间启用或编辑器；示例不是可直接导入的文件。本次不改游戏规则，也不把这些建议视为最终产品决定。

## 1. 首版要完成什么

让用户创建一个新种族，使用既有7种家园和正常2工坊开局，配置起始科学/工具、每轮收入、简单被动奖励及每轮一次主动能力。种族仍与家园、宫殿、奖励板分别选取。支持范围内的新种族不需要改主仓库代码；超出范围的机制由开发者扩充引擎，之后才能成为新配置选项。

第一阶段先做“内容定义→校验→加载→开局→服务端执行→界面选择/预览→回放”的闭环。可视化编辑器随后使用同一格式；不必先花时间设计完整编辑页面。

| 边界 | 首版核心范围 | 暂不纳入首版核心 |
|---|---|---|
| 用户能创建的内容 | 新种族及其能力；标题、说明、起始数值 | 自定义地图、家园、公共板、全局流程；其他内容类型以后复用同一能力接口 |
| 收入/直接奖励 | 金币、工具、受供应约束的学者、充能、得分、书籍 | 直接写魔力盘、任意状态字段、直接创造钥匙/建筑库存 |
| 选择 | 逐本选书色、单轨/逐次任选科学、四轨推进 | 自定义网页组件、任意多玩家交互、新的地图选择协议 |
| 触发 | 盘点中确定的少量成功事件、收入、个人pass、普通主动行动 | 任意插入结算中间点、取消/替换原行动、无限递归触发 |
| 次数 | 无额外次数限制、每轮N次、每局N次 | 增加主要行动预算、改多人回合顺序、复杂共享/重置次数规则 |
| 条件与计算 | 白名单条件、固定指标、整数/有限阈值表 | JS/Lua、字符串表达式、网络调用、自定义地图搜索 |

“每轮N次”等字段定义一般格式，初版编辑器可先只开放每轮一次。具体数值上限属于内容校验约束，应在实现前确定；不能靠宽松输入默许负成本、无限数量或无限选择。

## 2. 从现有能力提炼的事件接口

以下事件名称是提议的新接口，并不存在于当前引擎。执行主体默认是能力持有者，仅接收其自己的事件。公共行为仍由固定规则校验和执行。

| 提议触发点 | 对应代码入口/现有例子 | 需要携带的事实 | 触发边界 |
|---|---|---|---|
| `setup.beforePlacement` | 蜥蜴人起始科学，荒地书 | 本人、开局阶段 | 起始资源确定后、正式放置前，一次 |
| `setup.afterPlacement` | 发明家/僧侣开局奖励 | 本人、全部放置完成 | 所有起始建筑完成后一次；首版只开放基本资源/选择，不直接开放选能力板 |
| `income` | 奥尔马及宫殿/能力板收入 | 本人、轮次、当前只读局面 | 先计算收入明细，再由固定结算器发放，包含首轮 |
| `building.resolved` | 航海家、SH12/SH13、FAV10 | actor、hex、resultKind、origin、neutral、phase | 覆盖新建/升级/降级/免费/中立现有入口；同一次建筑变化只发一次 |
| `spades.spent` | 哥布林 | actor、实际铲数、origin、phase | 同时接普通改造和中立改造；不能在获得铲机会时触发 |
| `scholar.sent` | 学者奖励板、FAV8 | actor、track、slot | 派遣成功后；`slot:null`也算；不能由其他科学推进伪造此事件 |
| `city.tileTaken` | 猫人/蜥蜴人 | actor、tileId、领取来源 | 成功扣库存并增加钥匙后；含SH11；与城市群形成区分 |
| `competency.taken` | 哲学家 | actor、id、本局市场color/row | 领取成功后，颜色从本局格位取，不能硬编码能力ID颜色 |
| `player.passed` | SH7、FAV4/5、贸易路线 | actor、轮次、换板前局面 | 换奖励板之前；包括第6轮；与全员pass后的科学结算分离 |
| `active` | 哲学家、FAV3、SH1/SH6/SH13 | actor、abilityId、合法参数 | 本人主要行动；资源费/次数与效果入队一次性提交 |

`building.resolved` 的订阅必须显式声明 `phase: actions`，才能复现当前建造得分边界。原动作失败则整个动作及其触发结果回滚。科学推进仍调用既有科学规则，不能由配置绕过钥匙、顶级占位或阶段计分。

首版不开放“获得金币后再触发”“每次得分后触发”等资源递归事件；由受控效果产生的基础科学/钥匙连锁继续执行固定规则。这可避免用户构造无限奖励循环，同时需要对奖励链总步数设定确定性上限。

## 3. 首版配置字段

| 字段 | 作用 | 约束 |
|---|---|---|
| `schemaVersion` | 内容包语法版本 | 与规则引擎版本分开；不认识就拒绝 |
| `packageId` / `version` | 作者命名空间、不可变发布版本 | 发布后编辑产生新版本；同版本不能覆盖 |
| `requires.capabilities` | 需要的配置能力集合 | 不支持任一能力则拒绝启用，不静默忽略 |
| `factions[].id` | 种族稳定ID | 带包命名空间，不依赖显示编号或中文名 |
| `name` / `description` | 展示文案 | 只用于展示，不执行；关键效果提示由配置生成并与作者说明并列 |
| `starting` | 初始科学/工具加值 | 仅允许白名单字段；遵守正式初始化时序 |
| `abilities[].id` | 能力稳定ID | 用于次数、来源日志、收入明细和响应关联 |
| `trigger` | 上节枚举触发点 | 每个能力一个触发点；一个种族可挂多个能力 |
| `conditions` | 事件/只读局面条件 | 枚举谓词组合；不接受表达式字符串 |
| `cost` | 主动资源成本 | 首版限固定非负金币/工具/学者；无支付选择；被动能力不允许隐式扣费 |
| `actionCost` | 是否消耗主要行动 | `active`首版必须为`primary`；被动/收入不占主要行动 |
| `limit` | 次数和重置范围 | 明确owner、ability、scope；默认不共用不同能力的次数 |
| `effects` | 有序效果列表 | 白名单操作；选择生成可持久化节点，不保存函数闭包 |

建议首批原语：

| 操作 | 参数/用途 | 必须复用的固定规则 |
|---|---|---|
| `gainResource` | `coins/tools/scholars`与整数数量 | 学者用 `gainScholar`，不直接加字段 |
| `chargePower` | 充能数量 | `gainPower`；不等同增加标记 |
| `awardPoints` | 整数或白名单指标计算值 | `awardPoints`并保存稳定来源 |
| `gainBook` | 固定色，或 `event.competencyColor` | 检查色值及事件类型；适合哲学家领取奖励 |
| `chooseBook` | 本数，每本独立选色 | 生成多个持久化书选择 |
| `advanceScience` | 固定轨或全部轨，各推进若干 | `advanceScience`、钥匙、阶段计分/收入补发 |
| `chooseScience` | `each`：N次各+1；`sameTrack`：一次选轨推进N | 两种模式不可混用；响应继续用科学固定规则 |

白名单条件先覆盖：行动阶段、结果建筑类型、沿河、地图边缘、是否存在非中立商会。指标候选覆盖：实际用铲数、玩家数、明确中立范围的建筑计数、不同建筑类型数、累计钥匙、最低科学、最高两轨之和、己方桥数。计算仅允许常数、指标乘常数和有限阈值表；每种指标都需要服务端和预览共享实现。A类表示适合这种表达方式，不意味着首个提交必须包含所有指标。

## 4. 完整示意：一个新种族

下面是新设计示例，不是现有奥尔马/哲学家的替代定义，不宣称平衡。它只组合起始数值、收入与选书主动能力。

```json
{
  "schemaVersion": "cellman-content/1-draft",
  "packageId": "example:learning-pack",
  "version": "0.1.0",
  "requires": {
    "capabilities": ["faction-basic", "income-basic", "active-basic", "choice-book"]
  },
  "factions": [
    {
      "id": "example:learning-pack:archivists",
      "name": "档案学者",
      "description": "起始银行学+1；每轮收入2金币；每轮一次，支付1工具获得一本任选书。",
      "starting": { "scienceBonus": [1, 0, 0, 0], "toolsBonus": 0 },
      "abilities": [
        {
          "id": "income",
          "trigger": "income",
          "effects": [{ "type": "gainResource", "resource": "coins", "amount": 2 }]
        },
        {
          "id": "archive",
          "trigger": "active",
          "actionCost": "primary",
          "cost": { "tools": 1 },
          "limit": { "scope": "round", "count": 1 },
          "effects": [{ "type": "chooseBook", "amount": 1 }]
        }
      ]
    }
  ]
}
```

执行过程：服务端先校验当前轮次、行动权、可用次数和工具，原子地扣1工具、占用本轮能力次数、消耗主要行动并创建书色待选项；玩家选色后得书。刷新或重连继续同一选择，不能重新扣费/占次数；重复提交沿用现有 `commandId` 保护；私人回合撤销按已有规则恢复整条状态。首版此书选择不可放弃，不需要设计资源退款。

示例中 `abilities[].id` 在所属种族内唯一；运行时完整来源由包ID、种族ID、能力ID和本局固定内容引用组成。`income` 不用主动次数计数器：每轮固定收入阶段仅调度一次，计算预览本身不消耗次数。

## 5. B/C 类能力怎样处理

| 盘点中的机制 | 建议安排 | 开放前必须证明 |
|---|---|---|
| 免费铲/桥/工坊/商会 | 第二小步封装固定操作（B）；不允许任意覆盖可达性 | 免费部分与付费部分、库存、放弃、蹭魔、城市、选择过程中局面变化都正确 |
| 领取能力板/城市板 | B，调用完整取得流程 | 市场/库存、颜色行列、钥匙、种族奖励、二次选择不能漏掉 |
| 免费科技提升 | B，调用既有函数 | 上限跳过、升级奖励、轮次得分、双轨顺序 |
| 特定成本/科学奖励修正 | B，按操作类型建立专门接口 | 预览报价与最终扣费一致，修正范围互不污染 |
| 中立放置 | B，但需明确无法放置时的策略 | 改造费、建筑计数、收入来源、优先级、无点时其他效果的行为 |
| 鼹鼠/飞行/临时航海范围/河流建城 | C，保留代码 | 通行付费、分步授权、城市连接与终局网络各自语义 |
| 僧侣/奥尔马特殊开局 | C，保留代码 | 放置队列、建筑选择、剩余库存、开局派生选择 |
| 通灵者额外主要行动、附属建筑 | C，保留代码 | 行动预算、存量限制、建城影响，不产生无限行动 |
| SH15奖励组顺序 | C，保留代码 | 组间选择、组内连续、派生奖励和对手响应插入点 |

因此，**能配置“奥尔马式收入”并不等于能配置完整奥尔马种族**。首版编辑器遇到需要C类机制的设计，应说明当前不支持；开发者可以实现新的受控能力类型。无需为了模仿FreeKill立即引入Lua或开放任意TypeScript执行。

## 6. 同一内容怎样参与校验、显示、收入和回放

建议将加载/校验后的内容编译成只读能力注册表，以本局固定内容为输入：

```text
内容包 + 格式校验 + 能力支持检查
                ↓
        本局不可变内容注册表
          ↙         ↓          ↘
    合法行动/选项   收入明细计算   服务端执行
          ↓         ↓          ↓
        客户端提示与预览      持久化待选/账本
                                  ↓
                         固定版本引擎重放命令
```

- 收入：扩展现有 `incomeSources` 的纯计算路径，返回稳定来源与毛收入；发放时再处理魔力容量、学者供应和选择。预览不排队、不发奖、不计次数。
- 合法性：界面按钮/选项读取共享计算结果；服务端始终重验。原有 `getLegalActions` 是粗分类，不能直接当成每个能力参数的完整校验。
- 交互：书、科学复用既有选择面板；每个待选保存 `abilityId`、来源内容引用、响应人、参数及恢复位置。客户端不能传入通行授权等内部标记。
- 账本：同一事件触发的多个来源分开记录，采用固定排序；例如SH12与种族沿河分各出现一次。中文描述仅是展示。
- 事务：沿用权威 `applyAction` 与服务端事务、revision冲突、重复提交保护。解析配置不会替代这些保障。

固定本局内容时，建议保存：语法版本、精确引擎/解释器版本、完整规范化内容快照、依赖快照、内容哈希；资源文件引用也应不可变。哈希用于标识和校验，不能替代实际存档。作者更新创建新发布版本，新局可选择新版本，已开局继续旧版本；旧版本缺失时显式拒绝，不能回退到最新版。

`rulesVersion` 的现有冻结机制可以复用，但不能给新语义继续沿用engine-6。新解释器应进入新的规则版本，旧局继续分派原引擎；待选项结构变化也要明确存档兼容策略。若以后支持代码扩展，还需保存可恢复的代码构件及执行环境版本。

## 7. 最小实施顺序与验收标准

1. **先做内部注册表。** 用奥尔马的收入子能力、哲学家的选书主动子能力、航海家的沿河奖励、哥布林的用铲返币验证接口；替换原分支时防止新旧奖励双发。完整种族中C类行为仍保留代码，不假装已全部迁移。
2. **再做静态内容包加载。** 开发环境加载一个示例新种族，无需修改核心代码；严格拒绝未知字段/效果/版本和越界参数；保留全部现有内置内容。
3. **接入开局与固定快照。** 检查内容ID唯一、种族轮抽可用性、家园组合合法性；从正式开局流程初始化，保存本局内容快照。
4. **接通展示及恢复。** 新种族出现在选择列表，收入明细能解释来源，主动能力能选书/科学；重连恢复待选，回放与终局一致。
5. **最后提供用户创建/导入入口。** 表单只暴露已支持的配置项；房间明确显示启用内容及版本。统计分类和公开分享/收录政策另作产品决定。

最低验收集（未来实现时新增，本次未声称已覆盖）：

| 用例 | 必须观察到的结果 |
|---|---|
| 首轮/后续轮收入、刷新预览多次 | 正确结算一次，预览不修改状态 |
| 资源不足、已用次数、非本人回合 | 整个动作失败，资源/次数/待选无残留 |
| 主动能力待选时重连/重复提交 | 同一个选择恢复，不重复付费/发奖 |
| 科学跨8、跨9、顶级被占 | 钥匙、收入补发、上限与内置能力一致 |
| 沿河/非沿河、普通/中立工坊、多个计分来源 | 按明确条件触发，各来源恰好一次 |
| 免费与自费用铲、赠铲未使用、中立改造 | 哥布林式收益只按实际用量且不漏路径 |
| 第6轮pass产生科学选择 | 领取完成后才终局，不运行第6轮轮末科学奖励 |
| 作者发布新版后继续旧局并回放 | 使用旧快照及旧引擎，结果逐字段相同 |
| 未知效果/不兼容版本/过量选择 | 导入或开局明确失败，不部分启用、不隐式降级 |

这份建议的第一个可交付结果是可加载、可玩、可预览、可回放的新种族样例。完整能力编辑器和任意脚本扩展属于后续范围。
