## 已生效的防护

| 层次 | 实际参数/行为 |
| --- | --- |
| 游戏 API 入口 | 每 IP 平均 20 请求/秒、突发 80；两个 HTTPS 端口共享全站平均 40 请求/秒、突发 80 |
| 游戏静态资源 | 每 IP 平均 30 请求/秒、突发 90；与 API 分开，避免一次加载资源耗掉行动预算 |
| Nginx 并发 | 游戏站每 IP 48、站点总计 240 个被计数的并发请求；不等同于能支持 240 名玩家 |
| 同机其他 Web 入口 | 继承较宽的每 IP 30 请求/秒/突发 120、合计 60 请求/秒/突发 120，以及每 IP 64/合计 320 并发上限；Nature HTTP/HTTPS 验证正常。游戏站用自己的更紧限制覆盖这些 HTTP 级默认值 |
| 超额响应 | 游戏站返回 HTTP 429、JSON `RATE_LIMIT` 与 `Retry-After: 15`；前端能显示已有中文限流说明。应用自身的 429 保留其实际重试时间 |
| 请求超时 | 游戏站请求头/请求体 10 秒、代理连接 3 秒、代理发送 15 秒、响应发送 30 秒；SSE 保留 70 秒上游读取超时与 15 秒心跳 |
| 房间总额 | 每账号同时参与最多 100 个未结束房间；等待与进行中合计，服务端事务校验 |
| 开房/加入限频 | 创建每账号 12 次/10 分钟；加入每账号 30 次/分钟；不同会话共享同一账号预算 |
| 高开销操作 | 预览每账号 90 次/分钟；个人统计、全站统计、回放分别 20 次/分钟；悔棋申请 10 次/分钟 |
| SSE 连接 | 每账号 8、每 IP 32、全进程 160 条；新开连接每账号 60 次/分钟。拒绝/断开释放额度，重复关闭不会误释放别人的额度 |
| 慢消费者 | 写出无法及时消化时关闭流，交给浏览器重连；心跳鉴权不会并发堆积 |
| 空闲日志读取 | 时钟/悔棋状态仍刷新，无新版本时不再重复下载最近 100 条日志；有变化按版本增量抓取，每轮刷新最多 5 页 |
| 应用资源 | CPU 上限相当于 1 核，内存高水位 384 MiB、硬上限 512 MiB、文件描述符 4096、任务数 128；独立用户及既有沙箱设置保留 |
| 数据库应用角色 | `cellman` 最多 20 个连接；语句 10 秒、锁等待 3 秒、空闲事务 15 秒。仅作用于该角色新会话，postgres 管理角色全局值保持不变 |
| SSH | 关闭密码与键盘交互登录；root 仅密钥；最多 3 次认证尝试、登录宽限 30 秒。配置后以独立新连接验证，再取消 3 分钟自动回退 |
| 日志保留 | journal 磁盘上限 512 MiB、最长 14 天、保留至少 2 GiB 空间；Nginx 20 MiB 大小触发轮转，每小时检查，保留原有 14 份压缩策略。检查后的 journal 约 130 MiB |
| 本机健康检查 | `cellman-health.timer` 每 5 分钟检查服务、内存、磁盘、备份时效与证书临期，结果写 journal 和 `/var/lib/cellman-health/status.json`。没有外部收件人，不宣称已经有邮件/手机告警 |

请求限流是平均速率加突发额度，不是“瞬时第 21 个请求必定拒绝”。这些阈值是当前小服务器的初始保护值，不是容量保证。独立应用单进程内存计数适用于当前单实例；增加实例时需共享限额或重新设计。

- 未配置定期异地备份、外部通知收件人或自动封禁服务；本机健康状态与日志可查，但不等同于离开电脑仍会收到报警。
- 没有增加多本书批量选择或日志点击定位地图，遵守用户暂不补齐的决定。
