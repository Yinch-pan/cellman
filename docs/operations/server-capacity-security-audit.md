## 发现与优先级

### P1：入口没有请求速率及并发连接限制

`nginx -T` 有效配置中没有 `limit_req`/`limit_conn`。应用限流之前仍需处理连接、代理和部分请求工作；大量客户端/IP 或持续连接可能耗尽资源。SSE 每条长连接还会进行定时鉴权；`events.setMaxListeners(1000)` 是监听器告警阈值，不是连接上限。

建议对游戏站点 443 与 8443 共用每 IP 与全站限流区；对 API 超额返回 429 并告知重试。静态资源与 API 分开，SSE 设单独并发上限，应用增加每账号连接计数和关闭清理。同一局多个玩家、同一网络和多标签页需要保留合理突发额度，不能直接套“每 IP 一条连接”。阈值须通过本地正常四人局、慢客户端和限流边界测试后确定。

### P1：100 个房间上限尚未上线

线上没有 `apps/server/src/rooms/participation.ts`，房间服务没有本地新增的参与总额检查。这与之前“先本地测试，不发布”的范围一致。`/rooms` 查询的 `LIMIT 100` 只限制返回结果，不限制创建数量。

下一次安全补丁需要明确包含这项功能及迁移；同时针对创建/加入房间设置操作速率限制。每账号配额不能阻止大量账号或大量 IP，因此仍需配合入口限制、注册/发信总量预算，必要时再增加挑战验证。

### P1：SSH 与主机网络边界需要收紧

- 有效 SSH 配置为 `PermitRootLogin yes`、`PasswordAuthentication yes`；当前连接已经使用密钥。
- UFW inactive；nftables input 默认 accept，主要为 Tailscale 规则。**这不意味着没有阿里云安全组防护**，本次未获得安全组规则。
- 8889 由 `proxy-rotator.service`（Webshare Proxy Rotator）以 root 运行，绑定 `0.0.0.0`。从本机连接公网 8889 超时，不能声称已对公网开放。它不是游戏服务，本次未停止或修改。

建议先确认云安全组与管理来源，SSH 优先限制到 Tailscale 或可信管理来源；验证第二个密钥登录会话及云控制台救援路径后，再禁用密码认证。其他服务端口按实际用途限制来源，保留 Nature 和现有 Tailscale；不能盲目开启默认拒绝策略而锁掉管理或其他项目。

### P2：重接口和数据库缺少明确工作量上限

当前统计读取全部已结束局面，回放/悔棋读取该局完整命令；邮件检查每 15 秒扫描候选对局，生命周期每分钟检查进行中对局。历史增加后，这些路径会比单条日志追加更显著。

建议：日志按版本增量获取、终局统计预计算/短缓存、回放及悔棋限频、批量后台扫描只处理必要对象。给应用数据库角色配置合适的查询/锁/空闲事务超时，而不是贸然更改整台数据库全局行为；迁移和维护需要不同预算。为请求排队和高开销动作设明确上限，资源不足时快速失败而非无界堆积。

### P2：监控与备份覆盖不足

- 系统 journal 约 2.5 GiB，比游戏数据库大得多。建议设置合理的日志磁盘保留上限；未在本轮删除日志。
- 无 swap；可考虑少量 swap 作为瞬时内存保护，但它不增加处理能力，持续交换会拖慢服务。
- 同机备份不能覆盖服务器/磁盘整体故障；补异地备份并验证恢复。
- 加 CPU、可用内存、磁盘、5xx/429、请求延迟、数据库连接及备份失败告警。
- 证书当前到北京时间 2026-10-30 05:51:09；续期定时任务存在，但应有到期告警，不能以定时器存在代替后续续期成功。

## 扫描与云侧限制

当前访问日志样本为当天 338 行，能看到 `/.env`、`/index.php` 等常见自动探测路径；整体样本没有显示高流量洪泛。不能因此断言服务器没有被攻击或完全安全，也没有据此宣称存在入侵。

阿里云官方说明 Anti-DDoS Basic 提供网络/传输层防护，但不覆盖 HTTP Flood/CC 等应用层攻击，超过防护能力还可能进入黑洞。**本机 Nginx 限流无法阻止上游带宽被打满**。这台实例的带宽套餐、防护阈值、告警设置和安全组需要云控制台进一步核实；SSH 资源检查无法证明这些配置。若需要更强入口防护，再评估有域名的 WAF/CDN 接入、SSE 支持、8443 端口支持及源站来源限制，避免接入后仍可绕过源站。

3. 核对云安全组与备用管理入口，再收紧 SSH 和不必要端口。原有代理及 Nature 另行确认用途，不擅自关闭。
