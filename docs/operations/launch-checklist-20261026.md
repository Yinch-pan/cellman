## 运维入口

- 站点：`https://8.210.238.62:8443/`；帮助：`https://8.210.238.62:8443/#/support`。
- 开发电脑状态：Windows“文档”目录下 `cellman-operations\status.json`（本机为 `C:\Users\yinch\Documents\cellman-operations\status.json`）；最近输出：`last-run.log`；备份：`backups\`。不要把其中的数据库文件或凭据提交到 Git。使用文档目录是为了避免打包桌面应用的 LocalAppData 重定向导致计划任务找不到配置。
- 手动检查：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run-external-ops.ps1`。加 `-TestAlert` 会实际发送测试邮件到配置地址。
- 重装电脑、更换 Windows 用户或修改 SMTP 密码后，重新运行 `scripts/install-external-ops.ps1`。DPAPI 文件不能直接复制给其他 Windows 用户使用。脚本默认复用当前 SSH 信任和身份，不会自动接受未知主机密钥。
- 计划任务运行前提是该用户已登录；会话锁屏可以运行。任务启动隐藏窗口，不要求保存 Windows 密码。
- 服务器状态：`systemctl list-timers 'cellman-*'`、`journalctl -u cellman-health.service -n 20`、`cat /var/lib/cellman-health/status.json`、`cat /var/lib/cellman-restore/status.json`。
- 主动备份/恢复演练：`systemctl start cellman-backup.service`，然后 `systemctl start cellman-restore-check.service`。恢复演练只写入新建的临时数据库，不会覆盖线上数据库。

限制：服务器和开发电脑共用当前 SMTP 提供方；SMTP 整体不可用时，脚本记录失败，但无法通过同一 SMTP 发出失败邮件。离线电脑不能给自己发离线告警。`mail-status` 仅证明应用启用了邮件配置，不等于每封业务邮件都最终进入收件箱。备份包含账号和对局数据，需保护电脑登录与磁盘；它是数据库灾备，不包含云账号、SSH 私钥和 SMTP 凭据的完整灾后恢复保管方案。
