# 文案维护与板块编号

本次接入前，网页文案直接写在 React 组件和规则定义中，没有统一 i18n。现在网页的账号、大厅、房间、对局、提示、错误和规则说明使用独立语言目录。当前交付中文；多语言加载、缺失项回退和语言切换机制已具备，但没有交付完整英文翻译。服务器发出的邮件正文尚未纳入网页语言目录。

## 修改翻译

- 中文目录：`apps/web/src/i18n/locales/zh-CN.json`。
- 通用术语以 `term.` 开头，例如 `term.power` 为“能量”、`term.building.guild` 为“公会”、`term.building.school` 为“学院”。修改一次，引用该术语的句子一起更新。
- 单条文案在目录中搜索可见文字；`sources.json` 记录提取时的原文、文件和行号，便于定位。格式化后行号可能变化，键保持稳定。
- 保留 `{p0}` 等参数和 `{{term.power}}` 等术语引用。参数内容按原样显示，不作为翻译模板解释，也不注入 HTML。
- `content.*.description` 管理种族、宫殿、奖励板和革新说明；能力板效果在 `ui.i18n.content.*`。编号不属于可自由翻译的名字。

例如把 `term.power` 改为另一个确定的译名，即可统一相关界面；无需修改规则引擎。开发服务器会更新语言目录，生产环境需重新构建发布。

新增语言：添加 `locales/en.json` 等字典，在 `i18n/index.ts` 导入并注册。缺失键回退中文；注册两种以上语言后导航显示语言选择。选择保存在 `cellman-locale`，切换时重新加载页面，使模块级标签同步更新。没有注册的语言回退中文。

```powershell
node --import tsx scripts/extract-ui-i18n.mjs
node --import tsx scripts/extract-ui-i18n.mjs --check
node node_modules/vitest/vitest.mjs run apps/web/test/i18n.test.ts
```

提取脚本保留已修改的译文，不用原始文案覆盖人工校正。检查模式查找尚未提取的中文界面字符串。它不会自动完成翻译质量审核。历史规则事件由显示适配器翻译，不重写旧存档；未知历史文本保留原文。

## 编号依据与边界

参考用户提供的《大创造时代新手攻略 v1.0 正式版（2023）》：第 3 页缩写，第 10–14 页宫殿章节，第 18 页能力板图示。原 PDF 位于用户提供的临时附件路径，不作为运行时依赖。

之前“工具宫殿”“河港宫殿”以及奖励板的短标题是项目按效果编写的概括，没有核实为正式名称；界面已改用固定编号，并保留效果说明。

Snellman 的 [操作说明](https://terra.snellman.net/usage/) 使用 FAV、BON、TW 等代码。该网站说明的是《神秘大地》，此处只参考代码形式，不借用其板块编号对应关系。

2026-10-26 核对 BGA 后，修订了原来的项目编号。**FAV、BON、SH、TW 前缀是本项目沿用的交流格式；BGA 提示使用“能力板块 n”“奖励板块 n”“宫殿 n”，不能把这些前缀称为 BGA 原文。BGA 结算统计确实使用 E14 等革新代码。** 编号映射保存在 `apps/web/src/i18n/tile-codes.ts`，不能根据市场位置或随机排序生成。
